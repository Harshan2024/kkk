## 1. Overview
Validation of database transactions, constraints, integrity, index layouts, and connections. In production, CarbonTracker AI connects to a PostgreSQL instance. In development/testing, it connects to a local SQLite database using custom StaticPool settings to prevent multi-threaded conflicts.

---

## 2. Relational Schema & Constraints Audit

### Schema Tables Inspected
- `users`: Holds usernames, email (unique, indexed), password hashes, XP, and level.
- `activities`: Stores inputs, calculated emission values, categories, regions, and dates. Foreign key points to `users.id` (on delete cascade).
- `chat_messages`: Holds chat dialogue context. Foreign key points to `users.id`.
- `ai_insights`: Priority tips generated by NLP.
- `trend_records`: Relational trends data.

### Constraint Enforcement Checked
- **Unique Indexes:** Checked `users.email`. Attempting to register an existing email correctly raises a `UniqueViolation` and returns an error response.
- **Foreign Keys:** Checked foreign key integrity. Deleting a user cascade-deletes all associated `activities` and `chat_messages` cleanly. No orphan records remain.
- **Null Safety:** Checked table column definitions. Non-nullable fields (e.g. `users.hashed_password`) reject empty values immediately.

---

## 3. Transactional Safety & Pool Management
- **Connection Pool Configuration:**
  - `pool_size`: 20
  - `max_overflow`: 40
  - `pool_timeout`: 30
  - `pool_recycle`: 1800
- **Safety Features:**
  - **Auto-Reconnect:** If a query fails due to a broken connection, uvicorn automatically attempts a reconnect.
  - **Thread Safety:** The SQLAlchemy sessionmaker is scoped to prevent cross-request leakage.
  - **Deadlock Mitigation:** Long-running database operations use query-level timeouts.

---

## 4. Certification
The database layer enforces relational constraints, is protected against orphan records, and isolates concurrent transactions correctly.
